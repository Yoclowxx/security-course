# ПР №3. Права доступа Linux и управление пользователями

## 1. Пользователи и группы

Созданные пользователи и их роли:
| Пользователь | Группа | Роль |
|---|---|---|
| alice | developers | Администратор проекта |
| bob | developers | Разработчик |
| carol | auditors | Аудитор |

Поля /etc/passwd (разбор строки alice):
`alice:x:1001:1001:Alice,,,:/home/alice:/bin/bash`

| Поле | Значение |
|------|----------|
| alice | Имя пользователя |
| x | Пароль (в /etc/shadow) |
| 1001 | UID |
| 1001 | GID |
| Alice,,, | Комментарий |
| /home/alice | Домашняя папка |
| /bin/bash | Оболочка |

**/etc/shadow:** хранит хэши паролей. Недоступен обычным пользователям (только root) из соображений безопасности.

## 2. Права доступа chmod/chown

**Результаты:**
- bob (в группе developers) при 750: **не мог** создать файл, т.к. у группы нет права записи
- после 770: **создал** файл (группа получила полный доступ)
- carol (не в группе) при 770: **не может** войти (other=0)

## 3. ACL

Задача: дать carol доступ на чтение без изменения группы.
Команда: `setfacl -m u:carol:r-x /srv/project/code`

Вывод getfacl после изменения:
```# file: /srv/project/code
# owner: alice
# group: developers
user::rwx
user:carol:r-x
group::rwx
mask::rwx
# вставить вывод команды
```
 carol видит файлы (ls работает), но не может записывать (touch ошибка).
## 4. sudo-политики

| Пользователь | Разрешено | Ограничение |
|---|---|---|
| alice | Всё (NOPASSWD) | Нет |
| bob | apt, apt-get | Только пакетный менеджер |
| carol | journalctl, cat /var/log/* | Только просмотр логов |

## 5. PAM

Модуль pam_unix.so в /etc/pam.d/sudo: модуль стандартной UNIX-аутентификации
Что означает required: при ошибке аутентификация не проходит
Как добавить минимальную длину пароля 12 символов: password requisite pam_pwquality.minlen=12

## 7. Контрольные вопросы

**1. chmod 640** — владелец читает и пишет (6), группа читает (4), остальные ничего (0). Читают владелец и группа.

**2. setuid** — запуск файла от имени владельца файла (/bin/passwd). **sudo** — выполнение команды от root по настройкам /etc/sudoers.

**3. /etc/shadow** доступен только root, чтобы злоумышленник не мог скопировать хэши паролей.

**4. sudo bash** даст bob полноценную root-оболочку, снимая все ограничения.

**5. su** требует пароль целевого пользователя и даёт полную оболочку. **sudo** требует пароль текущего пользователя и выполняет одну команду с гибкими ограничениями.

**6.** Добавить в /etc/sudoers `bob ALL=(ALL) !ALL` перед групповым правилом.
